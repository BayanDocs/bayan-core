# F13: importing an update with many overlapping marks into a replica that has a subscriber costs time and memory cubic in the number of marks (report §7 F13, §8.2, §8.3). Measured 2026-10-08 on commit d64ec12 (Loro 1.16.2, Rust 1.99.0, release builds, x86-64 Linux) on the machine of results/README.md, while other jobs ran (load averages 5 to 9 during the subscribed imports), so the times vary widely; the memory figures do not depend on the load.
# Method: a scratch generator (not committed; it is a denial-of-service reproduction) builds one update from an empty document: a story of 2n+10 characters and n comment highlights `cmt:<id>`, each with its own 32-digit identifier and no comment entity, on the ranges [i, L-i] (nested), all on the same range (identical) or on [i, i+1) (disjoint). The update is imported once per process: through the adapter's Doc::import with ImportLimits::UPDATE, which every case passes (51 KB, 1 to 3 changes and 4,010 operations at n = 1,000), into a document with no subscriber, with a no-op subscriber, or with the adapter's undo manager; and through the model (Document::replica, which attaches the undo manager first, then Document::import). Peak memory is the process's VmHWM.
# Profile (callgrind, n = 150, nested, a no-op subscriber): 98.3% of the import's instructions are in RichtextState::apply_diff_and_convert (loro-internal src/state/richtext_state.rs:379), which runs only while the document records events: for each mark's end it turns each segment's whole style set into a new map (to_option_map, line 550) and composes n deltas (lines 568 and 571), so nested marks build about n^3/3 map entries.

Growth between sizes, with a subscriber: memory exponent 2.82 (100 to 250), 3.00 (250 to 350), 2.92 (350 to 500); time exponent 2.56 to about 3 (the largest step is inflated by allocating 5 GiB under load). Without a subscriber the exponent rises from about 1.8 to 3.3 between n = 50 and 1,000, at times 250 to 400 times smaller. normalize() grows with the number of mark entries (n^2), so linearly in what it reads.
